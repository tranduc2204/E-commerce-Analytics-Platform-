E-COMMERCE ANALYTICS PLATFORM — TECH STACK (kiến trúc Lakehouse, ELT)

Extract       | Python (pyarrow)                  | Script ingest dữ liệu Olist CSV, giả lập gọi API, ghi vào lake
Storage       | MinIO (S3-compatible)             | Object storage chứa toàn bộ data file Parquet
Table format  | Apache Iceberg                    | Biến file Parquet thành bảng: ACID, schema evolution, time travel, hidden partitioning
Catalog       | Nessie (iceberg) + file metastore (raw) | Nessie (REST v2, JDBC→Postgres) làm sổ đăng ký bảng Iceberg cho vùng curated; raw dùng file-based metastore trên MinIO. (Đã bỏ Hive Metastore.)
Query engine  | Trino                             | Engine SQL phân tán đọc/ghi Iceberg — thay vai trò warehouse
Transform     | dbt (adapter dbt-trino)           | Model staging → intermediate → marts, SCD2 snapshot (dim_customers), incremental merge (fct_orders), data tests, docs
Orchestration | Airflow                           | DAG chạy daily: extract → load → dbt build → alert khi fail
BI / Dashboard| Metabase hoặc Superset            | Nối Trino: dashboard GMV, MoM growth, tỷ lệ hủy đơn, giao trễ theo bang seller, phân khúc khách (NTILE)
Hạ tầng       | Docker + docker-compose           | ~6 service: MinIO, Nessie, Postgres, Trino, Airflow, Metabase (Trino cần 2–4GB RAM)
CI/CD         | GitHub Actions                    | Tự chạy dbt build + test trên mỗi PR

Ghi chú:
- Không có warehouse riêng: MinIO + Iceberg + Trino chính là warehouse (tách storage / compute).
- ELT thuần: load raw nguyên trạng vào Iceberg trước, mọi transform chạy trong lake qua dbt.
- Partition fct_orders bằng hidden partitioning: month(order_purchase_timestamp).
